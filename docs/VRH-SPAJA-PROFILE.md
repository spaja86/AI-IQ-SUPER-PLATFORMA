# VRH SPAJA strict profile v0.3

User-approved next phase after #1318. Adds central structured SPAJA profile, delegates unchanged runSpajaPetlja. Numerical code and existing direct APIs not modified. No generic any-loop/any-branch graph or Java translation.

Required input: start,end,step,target,sequence,maxIterations,maxDurationMs,status,spajaSegments,spajaTransferPolicy,spajaExportFields,spajaImportTarget. Finite numeric magnitude <=1e6; sequence <=1000; iteration/duration limits integer 1..1000; canonical status. Max ten explicit segments and 35 configured calls total; unique loops within each segment. Every segment explicitly declares RANGE/TARGET/SEQUENCE and importFromPrevious boolean. First segment cannot import a nonexistent predecessor. Same existing 35-loop classification as individual profiles. SPAJA self-recursion, UMBREL and DURMITOR rejected.

Only strict transfer policy enabled: incomplete child returns immediately; no later segment consumes stale output. Direct runtime fallback remains unchanged but cannot be invoked through this new profile until provenance behavior is reviewed. Export fields output/iterations/warnings-count explicit, unique, <=3; import target start/end/target/sequence. Export sums selected fields into one numeric value; import applies latest successful export to first call in later segment opting in. Other calls in that segment do not automatically import. Limits refer to runtime's shared SPAJA guard, passed as remaining iteration/time allowance to children; maxDurationMs is best-effort synchronous elapsed guard, not hard wall-clock isolation.

## Trace / provenance limitation
Existing PetljaResult preserves tagged child status trails, warnings and aggregate trace, but does not expose separate exact export/import events or all child result objects. This PR does NOT invent those events from the configured plan or claim full per-transfer provenance. In strict mode source is deterministically latest completed child, tested for FOR→DOK example. Full explicit event schema (source child/segment, value, fields, recipient, consumed/failed status) needs an additive reviewed runtime change and tests next.

## Verification
Tests compare exact existing SPAJA results for normal transfer, iteration cap, blocked status and zero-step; assert total reported iterations <= shared cap. FOR(1..3) exports 6 to DOK target, yielding 16 total; import disabled yields 7. Reject fallback, invalid segment binding, first-segment import, duplicate export fields, extra keys, nonfinite budget and Java target. Copied sequence/segments avoid caller mutation. Individual 35-profile and old reference-program regression tests run; targeted lint and isolated strict dispatcher typecheck. Full-platform build/CI/Preview, JDK, every transfer combination and strict wall-clock bounds not verified.

Spajascripte CALL syntax remains FOR-only. v0.3 is central structured numerical request, not new DSL syntax or production service. Existing authority/no-new-runtime-route boundaries unchanged. No deployment, payment, secrets, dependencies/config/workflows. Human review required; rollback removes v0.3 routing/profile/tests/docs, old paths untouched. UMBREL/DURMITOR global budgets remain separate blockers.
